## Current reliability claim

InfRing currently has a covered golden external runtime baseline for:

- `codex_cli`
- `claude_code`

This is a substrate/platform reliability claim. It proves the Gateway adapter
path can normalize external runtime terminal states. It is not a claim that
InfRing-native intelligence has reached parity with those engines.

Current live smoke status:

- constructor-backed primitive coverage: covered
- live bounded response smoke: passing for `codex_cli` and `claude_code`
- live real-work task proof: pending

## Proven primitive outcomes

The golden pair is covered for these primitive terminal outcomes:

- `completed_response`
- `permission_required`
- `approval_resume_completed`
- `typed_failure`

The covered shared primitives are:

- `native_direct_mutation_grant`
- `text_proposal_pause`
- `approval_resume_context`
- `visible_final_response`
- `typed_failure_projection`

## Proof scope

The current proof uses constructor-backed fake CLI turns. This validates the
adapter semantics and shared terminal-state machinery without invoking live
provider CLIs.

This proof answers:

- Does a normal completed turn carry visible response text?
- Does a text-emitted universal tool proposal pause as `permission_required`?
- Does approved resume context reach the resumed turn?
- Does a CLI crash/nonzero exit become a typed visible failed turn?
- Do Codex and Claude share Gateway-issued direct mutation grant semantics?

This proof does not answer:

- Whether a live provider subscription is active.
- Whether a live provider CLI can complete a real coding task today.
- Whether a non-golden runtime is production reliable.
- Whether InfRing-native orchestration is as capable as external engines.

## Live bounded response smoke

The live bounded response smoke is the first live-provider check for the golden
pair. It asks each runtime to return one exact marker without tools, file reads,
or mutation.

Passing this smoke means:

- the provider CLI is discoverable
- the adapter can launch the live CLI
- the turn returns a completed visible response
- the turn is not silently dropped

Passing this smoke does not mean:

- real coding tasks work through InfRing
- approval pause/resume works against a live provider turn
- artifact creation is reliable
- activity/decision traces have full parity with native provider UX

## Promotion gate

The external runtime promotion gate is active.

Non-golden external runtimes may remain selectable or cataloged, but they must
not be marked reliable, promoted, production-ready, baseline-covered, or
golden-pair-equivalent until they match the golden-pair primitive baseline with
proof.

Currently catalog-only engines:

- `grok_code`
- `opencode`
- `openclaw`
- `hermes_agent`
- `openhands`
- `openfang`
- `custom_socket_engine`

## Next reliability work

The next reliability step is live task testing for the golden pair:

- Run live Codex task turns through InfRing.
- Run live Claude Code task turns through InfRing.
- Compare native provider behavior with InfRing-mediated behavior.
- Record gaps for context continuity, approval pause/resume, artifact creation,
  activity/decision trace, model selection, and hard-failure reporting.

Only after Codex and Claude are boringly reliable should another runtime be
promoted from catalog-only status.
